# GitHub 参考项目与选题筛选

检索日期：2026-10-22。对象：首届芯光杯方向六「光电应用场景仿真」，指定软件 XGGD COSSIM。

本文是基于说明书、界面截图、用户已确认条件和公开项目的候选筛选，不是最终选题决定，也不是系统文献查新结论。未运行或复现下述外部仓库，未下载真实数据集。

## 1. 这次检索改变了什么

当前优先考虑：**用固定海岛背景完成具体视觉任务，在可控天气、光照和相机配置下评价误差，再比较配置方案。** 海岸海天陆边界提取最值得先试；图像域退化与软件内天气生成的一致性可作为进一步研究问题。林区云雾与烟的混淆有明确公开需求，可作为另一个应用候选。二维生态影像配准也是可探索的替代路线。

这些任务可以从人工图像标注起步，不把三维区域坐标、深度或自动框导出作为共同前提。此前「布设与几何覆盖评价」仍保留为有条件候选：区域几何及其与相机的对应关系尚未取得，不能视为已经可做。

## 2. 有没有找到同届同赛道的其他作品

**本轮未检到可核验的同届同赛道公开作品。** GitHub 仓库和文件检索词包括：芯光杯、Chip-Light Cup、光电应用场景仿真、新光光电、XGGD COSSIM、XGGD_COSSIM、XGGDCOSSIM、XN642；另用网络检索 `site:github.com` 交叉检查。XN642 只返回当前已有仓库。

因此，不能据此断言「别的参赛队一般都这样做」。下面均为相近研究的参考项目。未检到不等于不存在公开项目。

误命中 [H2020-COSSIM/COSSIM_framework](https://github.com/H2020-COSSIM/COSSIM_framework) 是计算系统协同仿真，不能当作指定光电软件的实例。

[赛事官方要求](https://www.csoe.org.cn/detail/2199.html)对应的是场景化光电系统建模、仿真计算、性能评估、方案优化，交付工程包、报告和 PPT。因此，选题应有明确任务和可核查指标，软件配置与场景建模应构成主要工作。

## 3. 软件能力核查

来源：本地《光电环境仿真软件使用说明书.docx》全部正文及关键界面截图；文字提取记录为 `outputs/manual_capabilities/manual_text.txt`，截图证据位于 `tmp/manual_features_audit/`。这是文档能力核查，尚不是软件运行验收。

|---|---|---|
| 时间与光照 | 年月日时分秒改变太阳光照角度；天空亮度系数、偏置。正文140–145行，图15/17 | 可比较时段和亮度条件；未证明镜头炫光、HDR或夜间信噪比的真实模型 |
| 天气与大气 | 晴、云、阴、雨、雪、雾、霾；界面有能见度m、温湿压、气溶胶模式、大气模式、风速XYZ。159–170行，图17 | 可选取能见度等作为输入因素；界面数值不等于现实标定已经成立 |
| 雨雪 | 雨云高、雨量mm/h、雨滴生成方式/序列图；雪云高、雪量、生成方式/序列图。图16 | 比单纯开关雨雪更丰富；需先核实用户版字段是否生效、可选范围和重复性 |
| 云 | 参数/贴图/粒子/模型方式，云类型、位置、透过率、亮度；截图另有高度、厚度、速度、粒子参数。147–158行，图16 | 适合云雾背景比较；不同方式取决于现有模型，粒子重复性未确认 |
| 海面 | 海平面高度、海况、风向、亮度系数/偏置、定向光及方向。210–221行，图27 | 可比较海岸背景和水域外观；不能推断真实波浪、潮汐、淹没、侵蚀过程，海况不自动驱动船姿态 |
| 场景特效 | 出现时间、持续时间、位置；截图火焰/烟效果有空间尺寸、缩放、透明度等。252–267行，图36 | 可做指定视觉效应的对照；不是经过验证的燃烧、烟羽扩散或灾害演变模型 |
| 相机与输出 | 位置、姿态、FOV、分辨率、灰度/彩色、帧率、位宽、响应系数/偏置、截图路径/倍率、校正字段。181–190行，图21/22 | 能比较观测和成像设置；响应系数/偏置不能称曝光或快门。噪声、畸变、模糊、滚动快门模型未确认 |
| 运动与坐标 | 相机和实体可设直线、圆周、自定义轨迹；有地面原点和相机坐标设置。143、191–199、222–250行 | 配置输入不等于逐帧位姿输出；地表拾取、区域边界和独立坐标转换仍未确认 |
| 保存与接口 | 可保存/打开/另存方案；按配置帧率保存序列图；手册列有外部驱动、同步和序列图回放。113–139、268–311行 | 可以手工组织对照实验；未证明有批处理、参数扫描、Python API、随机种子或严格同帧配对。图像回放不等于能向任意实采图加天气 |

用户确认条件优先于通用手册：**仅可见光灰度/彩色、单海岛、无真实数据集、不改引擎、不导入材质或配置反射率。** 软件包内虽见背景 FLT/OSG 目录，文件加密，目前不能由其确认区域几何可读。

尚不能作为既有条件：自动bbox/mask/深度/光流、逐帧真值时间戳、同步多相机、清晰与恶劣天气像素配对、物理真实性、真实环境迁移有效性。

## 4. GitHub 上值得借鉴的实际做法

| 项目及已核查内容 | 项目实际做法 | 我们能借什么，不能照搬什么 |
|---|---|---|
| [rain-rendering](https://github.com/astra-vision/rain-rendering)，README及[customdb.py](https://github.com/astra-vision/rain-rendering/blob/master/config/customdb.py) | 结合雨量、序列、相机参数生成降雨图像，用于受控比较 | 借环境因素与相机因素的实验组织；该项目需要深度，不能承诺直接接入 |
| [imagecorruptions](https://github.com/bethgelab/imagecorruptions)，README及[corruptions.py](https://github.com/bethgelab/imagecorruptions/blob/master/imagecorruptions/corruptions.py) | 分级施加雾、亮度、噪声等图像扰动；雾函数不使用场景深度 | 作为图像域退化对照。主要定位为未见扰动测试，不能训练测试使用同一组退化后宣称泛化 |
| [ImageNet-C/P](https://github.com/hendrycks/robustness) README | 分别评价多类退化及连续小扰动；作者提醒某些方法会改善一类条件、损害另一类条件 | 借平均、分组与稳定性比较原则；分类指标不能直接替换本项目的边界指标 |
| [LaRS evaluator](https://github.com/lojzezust/lars_evaluator)，[README](https://github.com/lojzezust/lars_evaluator/blob/master/README.md)、[metrics.py](https://github.com/lojzezust/lars_evaluator/blob/master/lars_eval/metrics.py)、配置 | 水域语义评价中单独计算水域边界指标，并保存分帧结果 | 借边界单独评价的思想；原分类和完整评估器依赖对应标注，不能将 obstacle 直接改称陆地或无标注套用 |
| [Restormer](https://github.com/swz30/Restormer)，[去雨说明](https://github.com/swz30/Restormer/blob/main/Deraining/README.md)及评价脚本 | 提供去雨等任务的预训练模型，使用清晰参考计算PSNR/SSIM | 可作去雨处理基线；不是已确认的全天气去雾模型，无严格配对不能硬算参考图指标 |
| [TransWeather](https://github.com/jeya-maria-jose/TransWeather) README | 联合处理不同天气退化 | 借多天气恢复思路；README注明代码库不完整，不能承诺开箱即用 |
| [CoastSnap](https://github.com/Coastal-Imaging-Research-Network/CoastSnap-Toolbox)，README及[影像纠正代码](https://github.com/Coastal-Imaging-Research-Network/CoastSnap-Toolbox/blob/master/GUI/CSPGrectifyImage.m) | 将海岸影像结合地面控制点、相机和潮位信息进行几何纠正 | 借海岸监测的应用链条；没有坐标控制点时只研究图像内边界，不承诺米级岸线成果 |
| [LightGlue](https://github.com/cvg/LightGlue) README | 提供图像对局部特征匹配及预训练权重，另有训练/评价工具 | 可作二维图像配准参考；README不证明它已解决本软件的天气变化问题，需另做控制实验 |
| [Wildfire Smoke Detection Research](https://github.com/aiformankind/wildfire-smoke-detection-research#what-we-are-working-on)及[camera项目](https://github.com/aiformankind/wildfire-smoke-detection-camera#false-positive-rate) | 作者明确提出改善云/雾与烟的区分，并分组统计历史模型的误报 | 有具体应用需求依据；其历史误报率不代表行业水平，也不能证明仿真训练会改善真实火灾预警 |

补充但不建议直接采用：[Fog simulation DBF](https://github.com/sakaridis/fog_simulation_DBF)需要真实图、深度及语义信息；[PyWaveLearn](https://github.com/caiostringari/pywavelearn)含岸基影像纠正、颜色特征和破碎波分析，但作者注明代码停维且研究被后续工作更新，不能直接将海况视觉效果当作真实海浪动力学。

这些项目提示四种可借鉴做法：参数化环境生成；分级退化与留出测试；图像处理与具体任务分别评价；把误差反馈到相机/观测配置。它们不构成参赛作品数量或常见程度的统计。

## 5. 可收紧的四个候选

### A. 海岸固定相机的海天陆边界与观测配置：优先做小规模试验

工作题名：**《复杂天气下海岛固定相机海天陆边界提取的稳定性评估与观测参数优化》**。

实际用途是海岸环境视频观察中的区域区分和边界记录。研究问题是：天气、太阳角和成像设置改变时，边界提取会在哪些条件下失效，配置调整是否改善结果？LaRS提供边界评价参考，但「在本软件场景上有多少改进」是待检验问题，尚不是结论。

软件贡献：固定背景与视点，改变少数天气/光照因素，比较视场、分辨率或响应设置；保存配置和输出，形成可重复案例。输出为图像内分区、边界误差和配置选择依据。人工标注少量图像，严重遮蔽处标不可判定区。

可核验指标包括区域重叠、边界位置误差、连续帧边界变化和不可判定比例。指标定义须与自建类别一致；不能照抄LaRS全套指标。只做可见区域标注时，不能再声称知道浓雾后被遮蔽的真实边界。该路线不要求先取得地面区域坐标，也不输出真实水位、潮汐、侵蚀量或米级岸线变化。

「优化」还需有任务与资源约束：先用画面中可辨识的固定端点限定待观察岸段，规定输出像素或计算资源上限，再比较配置。不同分辨率不能只比较原始像素误差，应同时报告归一化误差和资源开销；不同视场须确认包含同一待观察内容，避免得到「分辨率越高越好」的平凡结论。

### B. 图像域退化与软件内天气生成是否给出一致评价：适合作为研究问题

工作题名：**《两类天气退化生成方式对海岸边界算法评价一致性的影响》**。

图像域方法便宜、易组织；软件内天气设置可能产生不同的空间和光照表现。可检验问题是：在同一边界任务上，两类测试对处理方法的优劣判断是否一致？参照imagecorruptions和rain-rendering，但不能预设软件更真实或更优。

先确认软件天气输出的机制与重复性；不同生成方式的参数刻度不能直接等同，例如二维退化等级不等于软件能见度米数。应覆盖各自强度范围并交代比较依据，不能拿任意一档做「公平同强度」比较。相机与背景保持固定，结果仍以人工任务标注核验。

若软件内天气与对照在所测范围内没有实质差异，应如实报告；如有差异，只能证明评价结果对生成方式敏感，真实性优劣还需要实测或物理证据。此题研究表达更集中，但小试验证前不宜定为最终主线。

### C. 林区云雾与烟的混淆：应用需求最有直接证据，模型真实性风险较高

工作题名：**《云雾混淆条件下林区可见光烟雾提示的仿真评估与相机配置比较》**。

AI For Mankind作者仓库直接将云/雾与烟的区分列为改进目标；这比泛泛说「森林防火需要AI」更具体。可比较无烟有云雾、烟效应叠加云雾等情况，观察误报、漏报与配置变化的关系，避免只统计总体准确率。

先核实烟效应与云雾能否独立开关，且图像中确有可辨认差异。没有真实数据时只支持指定场景和烟效应下的比较，不支持真实烟羽、真实预警提前量或真实火灾检出率。不能用模型识别渲染器纹理的能力替代火灾识别能力。

### D. 生态监测图像的跨天气二维配准：可探索的非火灾替代

工作题名：**《天气与光照变化下海岛固定地物影像配准的稳定性评估》**。

应用需求是跨时段影像在比较前需要正确对应。LightGlue可提供匹配方法参考；天气变化是否影响本场景配准，以及怎样改善，是本次提出的待测问题，不是作者仓库已证实的缺陷。

可选择建筑或地形中的固定可见点，在两图上人工建立对应，用像素对应误差、错误匹配和成功率比较条件；不必先得到这些点的三维坐标。不能将整幅非平面地形强行视作一个平面，也不能将二维配准结果称为三维重建、目标姿态或距离真值。若人工也无法可靠对应，应标不可判定或暂缓。

## 6. 与比赛和政策的对应

比赛工作应围绕「场景/相机配置—仿真输出—任务评价—方案比较」展开。仅生成天气图片、仅跑一次开源模型，尚不能形成完整任务。图像恢复可以作为A或B中的对照模块，不必再单独扩成一个缺少应用对象的全天气增强课题。

政策联系分层表述：

- 软件应用与评价：2026年9月11日工信部对[《“人工智能+软件”专项行动实施方案》的官方解读](https://www.miit.gov.cn/xwfb/xwfbh/bxwfbh/art/2026/art_95c0b992336a4cb1b87ec3ccc576a669.html)谈及CAD/CAE/EDA与人工智能结合及设计仿真场景。这为国产仿真工具与视觉算法结合提供背景，但本项目并未修改软件内核或完成软件智能化升级。
- 海岸/生态图像观察：生态环境部[2026年8月13日发布会](https://www.mee.gov.cn/ywdt/zbft/202608/t20260813_1164026.shtml)强调智慧化监测及AI图像解译等应用。A、D可以联系监测影像的稳定获取与处理，不应扩张为水质、污染排放或生态状态测量。
- 林区提示： [《现代化应急体系建设“十五五”规划》](https://www.mee.gov.cn/zcwj/gwywj/202606/t20260612_1159169.shtml)涉及立体监测和森林草原火险治理。C联系视觉监测条件比较，不能据此宣称已有真实预警能力。

政策提供需求背景；具体用途、评价指标和方法贡献仍需由项目自身建立。上述候选没有经过文献/专利系统查新，不称「首次」或「领域空白」。

## 7. 下一步先做什么

先对A做一次小规模可行性试验，B作为可选研究问题保留：

1. 在现有海岛选择少量能清楚看见海、天、陆边界的固定视点，确认能够保存相机与环境配置及图像。
2. 每次只改一个因素，核实天气/能见度、太阳角、分辨率等字段确实影响输出；重复初始化观察差异。若某字段不生效，不继续围绕它设计实验。
3. 人工标注一小组可见区域和边界，记录不可判定处。按视点或场景区块留出评价图，避免同一机位相邻帧随机拆分造成成绩偏高。
4. 比较少数边界提取/处理方案，先确认任务有可测误差和可解释的配置差异，再扩展条件组合。方法选择不能使用留出结果反复调优。
5. 保留基线、分组结果、最差工况和失败例。连续帧误差并非独立样本，不用大量相邻帧冒充大量独立试验。

若清晰参考与天气图不能严格对齐，不计算成对PSNR/SSIM，不复制晴天标签充当所有天气的可见真值。若相机响应仅为等价的图像后处理，也不能包装成新光学硬件设计。

下一轮可交玻尔学术的检索问题：在海岸/环境视频边界提取中，已有研究怎样联合处理天气、光照和成像参数；图像域退化与场景天气生成的评价一致性有哪些已有工作；仅仿真与人工图像标注能支持怎样的结论。要求同时检索支持和反例，并核实以上工作题名是否与已有方法实质重复。
